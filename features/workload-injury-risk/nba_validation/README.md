# NBA公式トラッキングデータでの検証

[負荷・怪我リスク特徴量PoC](../README.md)と**同じ手法**（速度帯別距離・パーセンタイル基準のピーク速度・外れ値除去）を、Bリーグの自前パイプラインではなく、**永続IDが最初から付いている公式データ**で検証した。トラック断片化・ジャージOCRが一切不要な「正解に近い」データで、自分の手法が現実的な値を出すかを確認する目的。

## データ

- ソース: [linouk23/NBA-Player-Movements](https://github.com/linouk23/NBA-Player-Movements)（2015-16シーズン公式SportVUデータ、25Hz）
- 対象試合: 2016-01-01 CHA at TOR（gameid 0021500492）、フルゲーム
- 座標は公式データのフィート単位をメートルに変換して使用
- 99MBの生JSONと5.7MBの7zアーカイブはサードパーティの生データのためリポジトリには含めない（`.gitignore`で除外、再現手順は下記）

## 結果

19選手をフルゲーム（最大46分強の実トラッキング時間）で分析。最も出場時間が長かったNicolas Batum（CHA）は、移動距離2,772m・実トラッキング時間2,774.7秒（約46分）——**NBA選手の実測値として現実的な範囲**（一般にNBA選手は1試合2.5〜4km走ると言われる）。Bリーグ自前パイプラインと同じコードが、全く別の高品質データでも妥当な結果を出すことを確認できた。

詳細: `nba_workload_fullgame.json`（スクリプト実行で再生成可能）

## 重要な発見：ピーク速度のパーセンタイル基準はサンプル密度に依存する

Bリーグ分析（0〜70秒、サンプル数が少ない）では95パーセンタイルが妥当なピーク速度の代理指標になったが、フルゲーム（1選手あたり数万サンプル）では**95パーセンタイルも99パーセンタイルも実際のスプリント速度を大きく下回った**（Batumでp95=3.33m/s、p99=4.58m/s。実際のNBA選手のスプリット速度は7〜8m/s台に達する）。

**原因:** バスケットボールの試合時間の大半は歩行・ジョグで、スプリントはごく一部。サンプル数が増えるほど、percentile基準の「ピーク」は低速側のボリュームに埋もれて下振れする。

**示唆:** 短時間・高密度のクリップ（Bリーグ分析のような）では percentile 基準で十分だが、フルゲーム規模のデータでは「スプリント区間だけを抽出してからピークを測る」「移動平均を使わず生の最高速度を外れ値除去だけで評価する」といった設計変更が必要。これは実運用の怪我リスクモデルを作る際に直接効いてくる知見。

## 再現方法

```bash
# データ取得（約6MB、7zで圧縮済み）
curl -L -o game.7z "https://raw.githubusercontent.com/linouk23/NBA-Player-Movements/master/data/2016.NBA.Raw.SportVU.Game.Logs/01.01.2016.CHA.at.TOR.7z"
7z x game.7z   # brew install p7zip が必要

python3 analyze_nba_tracking.py
```

## 正直な限界

- 1試合のみの検証。他の試合・選手での再現性は未確認
- `active_tracked_s`は「隙間(dt>1秒)を除いた合計」であり、実際のコート上滞在時間（出場時間）とは厳密には異なる
- ノイズ除去の閾値（12m/s超を除外）はBリーグ分析と同じ値を流用しており、NBA選手の実際のトップスピード（9m/s超）を一部削ってしまっている可能性がある
